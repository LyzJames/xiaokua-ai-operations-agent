# 共享库存联动设计

状态：业务规则已确认，台账与逐店分配已经实现；验收日期 2026-10-13（北京时间）。适用于 Web 和飞书共同使用的多平台运营应用。

## 库存依据

以“组织 + 物理仓库 + 主 SKU”为库存池，各平台规格与其建立明确映射。平台 SKU 名称相同不自动认定为同一实物。未映射、多义映射、缺少订单明细时暂停该池的增库存操作，交由运营人员核实。

物理库存由负责人录入盘点基线，库存修正、收货和退货入库均产生需独立审批的台账操作。初次启用先核对未发货订单和已有平台库存，再开始自动记账，避免把历史销量重复扣减。

Amazon FBA 库存由 Amazon 保管，与商家自发货仓分别建池。读取 FBA 数量不能直接修改 FBA 实物库存，也不能把 FBA 数量复制到多个自发货店铺。FBA 跨渠道履约需要单独的出库任务与平台能力。

## 数量与分配

```text
可分配数量 = max(0, 实物在库数量 − 未发货订单预留 − 安全库存)
所有关联店铺的可售配额之和 ≤ 可分配数量
```

例：仓库有 100 件，未发货订单预留 10 件，安全库存 5 件，可分配 85 件。可将 Shopify 店铺 A 分配 50 件、店铺 B 分配 35 件。Amazon 自发货写入取得角色与完成适配后可使用相同配额契约；当前 Amazon FBA 不参与商家仓分配。各店配额由运营人员明确设置，系统检查总量；初期不按销量自动猜测分配比例。

安全库存按池配置；建议初始化为 5 件，运营人员可按商品供给与同步延迟调整。首次启用先同步、建立映射，再申请初始实物盘点并核对自动汇总的未发货预留，最后填写分配方案。平台历史窗口之外的未结订单须先人工对账，不能把未知预留当成 0。

## 订单生命周期

| 事件 | 台账行为 |
| --- | --- |
| 有效订单待发货 | 按已映射的订单明细预留，不提前扣实物在库数 |
| 订单修改或部分履约 | 依据已核实的明细数量变化调整预留；不能用整单状态猜测部分数量 |
| 发货确认 | 对实际发货数量扣实物库存，并释放对应预留 |
| 发货前取消 | 释放未发货部分预留 |
| 退款 | 记录售后状态；退款金额不代表实物回仓 |
| 退货收到且可再销售 | 经独立审批后增加实物库存 |
| 重复、乱序或缺字段事件 | 按平台、店铺、订单、明细和已核实版本去重；重读平台当前状态，缺少数量证据时停止自动记账 |

预留与台账修改在数据库事务中锁定库存池；重复同步、重启和并发订单不能重复预留或扣减。库存不足时登记差异，不生成负数库存或自动增加平台数量。

## 跨平台写入

联动生成一个带池版本、店铺目标数量和前后差异的分配方案，每个外部写入仍由不同于申请人的成员审批。

变更遵循“先减后增”：先降低需要让出配额的店铺，全部成功并回读后，再允许其他店铺增加配额。某一平台失败、超时或结果未知时，阻止后续增加，保留已经成功的结果与人工核实入口；不假设多个平台可以一起回滚。

审批后再次核对实物池版本、预留数量、权限与平台当前库存。发生变化则方案失效，重新生成。只允许已注册且已授权的实际平台适配器产生操作方案；FBA 独立只读，不与商家仓合并。

## 运行与验收

关联店铺订单、库存或明细同步不完整时冻结该池的增库存；有待核实写入的池也冻结重新分配。恢复需完成只读回查、差异处理和新一轮审批。记录每个池的同步时间及数据覆盖范围，不能把固定沙箱样例视为实时订单。

验收包括并发下单、重复/乱序事件、部分发货、取消、退款不入库、退货审批、跨店相同 SKU、库存不足、失败平台阻止增量、旧方案失效、任务恢复与组织隔离。

平台订单和库存写入不能组成跨平台原子事务；实际试运营还须验证平台通知与轮询延迟、限流、缺失明细和人工接管流程。配额与冻结规则用于控制可售数量，不能作为零超卖保证。

参考：[Shopify 库存比较并设置](https://shopify.dev/docs/api/admin-graphql/2026-10/mutations/inventorySetQuantities)、[Amazon FBA 库存](https://developer-docs.amazon.com/sp-api/docs/fba-inventory-api)、[AWS Saga 模式](https://docs.aws.amazon.com/prescriptive-guidance/latest/cloud-design-patterns/saga-orchestration.html)。

## 工作台使用顺序

1. 负责人创建库存池；同一组织/仓库/主 SKU 不重复建池。
2. 同步店铺，逐个选择平台规格与明确库存地点。首版一个规格对应一个仓库；FBA 池只绑定一个平台仓规格。
3. 运营成员申请初始盘点或入库，另一成员审批。台账自动记入已知未发货订单，历史已发货量不重复扣减。
4. 点击同步全部关联店铺，确认最近 5 分钟内订单与库存均完整；输入所有店配额并生成方案。
5. 另一成员分别批准减量；平台回读吻合后，系统才生成增量审批。旧池版本、旧平台库存或审批过期会停止执行。
6. 有未知结果时先只读核实，禁止重新发送写入。负责人核实并关闭旧方案后，再对账和解除冻结；不完整明细、超额可售或未结方案不会仅凭说明放行。
