# 公开发布与隐私检查

公开版本使用合成订单、商品、成员、客服咨询与消息。`example.invalid` 邮箱、`synthetic.myshopify.com`、`cli_demo_*`、`ou_demo_*`、DEMO 物流单号和演示密码是明确的研究占位符。

## 发布原则

1. 只从源码、通用模板、合成例子和重新拍摄的截图组成白名单发布目录；不上传整个原工作空间。
2. `.env`、`Key.txt`、数据库、加密密钥、会话、备份、真实平台验收脚本/上下文、旧平台截图、运行日志和历史打包文件均排除。
3. 公开文本检查常见 token、私钥、非示例联系人与机器路径；另外在私有本机比对实际凭据和平台标识，不打印这些值。
4. 每张新截图人工查看，只允许合成数据；原始图片不做伪造或遮盖。图片元数据检查排除 EXIF/XMP 等载荷。
5. 发布前后核对文件清单与内容哈希，并核对 Git 提交邮箱；只上传干净的新历史，使用 GitHub noreply 提交身份。

## 辅助扫描

```bash
uv run python scripts/check_publication.py
```

在 Git 仓库中默认检查 Git 跟踪文件，避免读取忽略的私人运行目录。检查一个准备发布的干净目录时使用：

```bash
uv run python scripts/check_publication.py --root PATH_TO_CLEAN_PUBLIC_TREE --all-files
```

扫描只报告相对文件名和问题类型，不输出匹配到的秘密。它是辅助工具，不能证明任意未来的业务数据都无隐私；新增图片、记录和导出仍须人工审查。

`docs/public-manifest.json` 记录公开文件及图片的哈希，`docs/screenshot-manifest.json` 记录本次拍摄步骤。机器用户名、私人邮箱和平台账号不写入这些清单。GitHub 公开账号名称及仓库地址是经授权的公开发布身份。

## 研究者贡献

请只提交合成数据。不要把真实客户消息粘到 Issue、PR、图片或公开模型提示中。发现泄露时，不要在公开 Issue 重复粘贴秘密；先撤销相关凭据，再使用 GitHub 的私下漏洞反馈途径（若仓库已开启）或自行联系维护者。

## 0.3 新增数据边界

角色步骤日志位于私有业务数据库，保存输入指纹和经校验或规则生成的结果，不保存原始模型请求/响应或密钥。分析结果仍可能包含组织业务信息，应按私密资料管理，不提交到 GitHub。

分类测试 JSON 只含类别、状态、计数和运行环境，不含参数、异常文本、机器目录或凭据。真实只读探针公开摘要只包含布尔结果、安全错误码及模型格式；不包含平台资源或账号标识。

技能下载属于当前组织的认证操作，ZIP 仅包含 SKILL.md 和引用证据，不附带脚本。真实组织导出的技能不能直接作为公开样例；本仓库 examples/skills 全部为合成模板。
