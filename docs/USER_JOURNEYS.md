# 三个完整电商业务的复现步骤

这三个故事覆盖前台购买 → 明确两店范围 → 同步/真实模型分析 → 库存预留 → 独立审批 → 两平台处理 → 最终回读/审计。当前结果与图片见 [测试报告](TEST_REPORT.md)，逐阶段来源见 [脱敏记录](journeys-acceptance.json)。这是开发店铺加 Amazon 托管沙箱的实际 API 验收，不是真实付费买家或真实仓库配送。

## 共同准备

1. 按 [总 README](../README.md) 构建并启动真实工作台，创建组织、负责人和另一名审批成员。请使用自己的账户；报告中的成员是由一个操作者控制的合成身份。
2. 按 [接入指南](INTEGRATIONS.md) 添加自己的 Shopify 和 Amazon SP-API 沙箱连接、DeepSeek 模型配置。Amazon 必须明确环境、区域和站点；飞书是可选入口。
3. 保持 `SHOPIFY_TEST_ONLY=true`。Shopify 仅使用开发店铺的 Test Payment Gateway / Bogus Gateway，确认买家结账显示测试网关；不要在真实付款网关使用测试步骤。准备德国、法国可配送区域及零费用测试运费。
4. 为每个案例创建独立测试商品、规格和 SKU，带 `xiaokua-test` 标签；可用库存 10，价格 19.90 USD，发布到自己的 Online Store。三个案例各用新订单、新 SKU，避免互相污染。
5. 在每个案例中，先添加 Amazon 独立虚拟 SKU，再申请入库 10；所有沙箱写入也要切换另一成员批准。Web「Amazon 沙箱」使用固定合成收货地址，国家可选择 US/DE/FR；这不检查生产可配送资格。
6. 真实买家前台加入一件商品，填合成姓名/联系信息及对应合成国家地址，使用网关公布的测试卡信息提交一次。到 Shopify 与 Web 核对：网页来源、测试标志、成功测试交易、库存 10 → 9。失败或结果未知时先核实，不重复点付款。
7. 在 Web 同时勾选 **Shopify 和 Amazon**，输入“同步并分析所选店铺”。查看同一聚合任务下两店同步和分析的四个子任务，六份角色结果应明确来自真实模型且通过校验；Amazon 订单标注官方静态样例。再指定当前 Shopify 订单号分析，确认没有混入其他案例订单或商品。
8. 在「共享库存」为该 SKU 建商家仓池，映射 Shopify 规格/地点，由另一成员批准合成开账 15、安全库存 5；同步后当前订单预留 1。另建 FBA 只读池，映射对应 Amazon SKU。两个仓库不共享可用量；真正试运营时开账须实地盘点，不能照抄 15。

## A · 德国履约与物流更正

使用德国买家新订单，完成共同准备。

1. 对关联 SKU 申请 MCF 数量 1、合成国家 DE，另一成员批准。回读 PROCESSING，并核对编号、SKU、数量、收货国家。
2. 分别申请并独立批准模拟订单 COMPLETE、包裹 OUT_FOR_DELIVERY、DELIVERED。查看每项回读证据；不要把模拟的包裹状态当成真实运输。
3. 在 Shopify 订单提出履约，使用合成运单信息并独立审批；同步已履约状态。再单独提出物流更正，批准后回读更正结果。本应用没有自动把 Amazon 运单写回 Shopify 的生产功能。
4. 两店同步结案：Shopify 已履约/库存 9；MCF COMPLETE/包裹 DELIVERED；本轮 FBA 可用 9、预留 1；商家仓 14/预留 0。平台读数以自己的回读为准，不强制预留为零。导出任务报告和审计，核对审计链。

## B · 法国撤销、退款与取消

使用法国买家另一笔新订单，完成共同准备。

1. 独立批准国家 FR、数量 1 的 MCF，核对 PROCESSING。
2. 买家在发货前撤销。申请并独立批准 MCF 取消，回读 CANCELLED；不要在发货完成后直接套用此取消步骤。
3. 在 Shopify 对原测试交易申请全额 19.90 USD 退款，另一成员批准。回读退款总额和净测试收款 0。
4. 另行申请 Shopify 取消及补库存，独立批准；核对取消没有再产生退款。金额按数值比较，`19.9` 与 `19.90` 等值。
5. 两店最终同步：Shopify 取消/库存 10；FBA 可用 10/预留 0；商家仓 15/预留 0。核对金额、审计和操作记录没有重复外部写入。

## C · 技能复用、商品改进与异常配送

使用德国买家第三笔新订单，完成共同准备；先分析同一订单并记录技能未启用时的结果。

1. 在「记忆与技能」导入 CSV/JSON 的十条合成客服记录：德国能效五条、法国本地退货五条。可下载工作台模板，字段示例见 [合成 CSV](../examples/support-synthetic.csv)；不要导入真实个人信息用于公开报告。
2. 勾选两店输入“学习客服经验”。确认生成一个全局学习任务和两个带来源证据的草稿，初始不启用。逐条核对后手动启用，再对同一德国订单分析；知识角色应引用德国技能，而不是以法国规则代替德国证据。
3. 提出无证据的 A+++ 商品说明，审批人拒绝；平台回读保持原说明。修订为“能效等级以适用规格的官方认证标签为准；法国退货安排须向商家确认”，批准后核对平台内容，并在买家前台确认可见。
4. 申请并批准 DE、数量 1 的 MCF；模拟 UNFULFILLABLE 并回读包裹。**先核实原渠道确实不能交付，再决定替代履约**；未知或仍在配送时停止，不能自动双发。本轮实际包裹是 UNDELIVERABLE。
5. 单独申请商家仓 Shopify 履约，由另一成员批准。核对 Shopify 已履约、库存 9、商家仓 14/预留 0；审计记录包含拒绝、批准、异常与后备处理。
6. FBA 本轮仍回读可用 9、预留 1，保留人工库存核实项，未自动补库存。不同沙箱运行可能返回不同状态，必须保留实际证据，不能为了符合故事改读数。

## 复现与试运营的区别

真实平台配置、OAuth 分发、真实付款退款网关、生产 Amazon 授权、实际地区配送与容量须在自己的环境另行验收。当前 Amazon 生产写入关闭；沙箱账号足以复现已实现的沙箱流程，生产只读需生产应用和卖家/供应商授权。细节见 [平台目录 README](../backend/production/platforms/README.md)。

三条新链路从 Web 驱动，飞书可进入同一服务，但本轮没有把历史真实消息/卡片验收写成新案例证据。公开仓库当前版本不含测试源码；可通过以上步骤使用自己的账号手工复现，测试者本机仍保留回归与验收脚本。
